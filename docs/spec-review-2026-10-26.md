## A. 阻塞：會改變實作

### A1. 漣漪剪輯沒有跨軌規則（§4、§5.1、§5.13）

- 現況：`Effect`、`Caption`、局部放大關鍵幀用時間軸時間；`Word`、`MaskObject`、`Suggestion` 用素材時間。V1 漣漪刪除與改字即剪只寫了「同素材的 A 片段一起剪」，沒寫 A1 要不要跟著漣漪，也沒寫 V2 以上、A2、A3、Effect、zoom 關鍵幀要不要一起左移。
- 後果：AI 導演先採用 proposeEffect、再採用 proposeCut，切點之後的特效全部錯位；A1 不漣漪就影音錯開。
- 建議：比照 Resolve，V1 漣漪時，切點之後所有未鎖定軌的片段、Effect、關鍵幀整體位移，鎖定軌不動；跨在切點上的 Effect 依比例裁短或刪除。寫進 §4 與 §5.1。

### A2. 字幕「推出」與「可手改」衝突（§4 `Caption`）

- 現況：Caption 由逐字稿推出，又可以手改；之後一重算，手改就被蓋掉。
- 建議：字幕是「Words＋斷句規則」的純函式，不另存文字。手改內容寫回 `Word.text`，斷點調整存成以 `wordIds` 為鍵的 override。

### A3. 三套算繪器，卻承諾「預覽＝輸出」；網頁版匯出沒排進時程（§5.4、§5.7、§5.10、§5.21、§8）

- 現況：
  - 預覽：`<video>`＋CSS＋canvas。
  - Windows 匯出：ffmpeg 濾鏡圖。
  - 網頁匯出：WebGL＋WebCodecs。
  - 字幕也有三種畫法：預覽 DOM 文字、Windows libass、網頁 canvas 文字。
- 網頁版匯出（P0）、WebCodecs 代理檔、OPFS、COOP／COEP 都沒有排進 §8。
- Windows 匯出要走多段管線：V1（遮罩＋放大）→ 解成畫格送進沙盒畫 3D → 讀回 → 疊 V2 以上 → 插件 → 字幕。§5.7 自己估 1080p 每秒雙向各 240 MB。
- 兩個選項，由開發者決定：
  - **(a) 網頁版縮小**：只做範例專案播放與剪輯，匯出請用 Windows 版。省掉一整條匯出管線。選這個的話，§5.22「所有功能可以預覽、播放、匯出」要改成「預覽與播放；匯出用 Windows 版」，§2 網頁版那一列的「匯出用 WebGL＋WebCodecs」也要拿掉。
  - **(b) 統一合成器**：預覽與兩版匯出都用同一個 WebGL 合成器＋WebCodecs 編碼（WebView2 也有 WebCodecs，Windows 上可走 Media Foundation 硬體編碼）；ffmpeg 只負責代理檔、解 WebCodecs 解不了的格式、抽 ASR 音訊。插件畫格不必離開 WebView，IPC 頻寬問題和兩次往返沙盒的多段管線都不存在；遮罩、放大、3D、字幕只寫一次。
- 不論選哪個，都要把 Q7 的 10/27 量測寫成有判準的決定，例如「10 分鐘多軌片段，WebCodecs 匯出時間 ≤ ffmpeg 的 1.5 倍就走 (b)」。

### A4. P0 依賴 P1（§2、§5.22、§1、§11）

- 範例專案是 P0，內容卻列了 SAM 遮罩、AI 導演建議、局部放大、逐字高亮、配樂，全是 P1。
- §1 成功標準含「遮罩」（P1-5）。
- §11 的「P0 內再排序：剪輯＞字幕＞匯出＞遮罩；必要時遮罩只做框狀」是 D19 之前的舊文，和「核心＝Vibe」矛盾。
- 建議：§5.22 加一句「P1 被砍時，範例專案的內容跟著縮減」；§1 成功標準的遮罩標成 P1；§11 那一列改成 D19 的順序。

### A5. 範例專案的素材有循環依賴（§5.22、§8、§9）

- §5.22 寫 11/3 用當晚錄的宣傳素材剪範例；§9 寫 11/3 晚上才錄、11/4 只剪不改功能。範例專案實際上只能在 11/3 深夜到 11/4 做，而範例要預先算好 AI 結果、打包上 Pages。
- 建議：提早（例如 10/31）錄一段 2 分鐘英文短片，含假 API 金鑰。同一支片當 ASR 英文實測、贅詞實測與範例專案的素材，11/3 只做打包。

## C. 技術點

### C1. 局部放大的 ffmpeg 寫法做不出變倍率（§5.19）——已實測

- 實測（ffmpeg 9.0.1）：`crop=w='640-t*100':h=360` 直接報 `Error when evaluating the expression`。`crop` 的 w／h 只在設定時求值一次，只有 x／y 能逐格變。
- 實測可行：`scale=w='iw*z(t)':h='ih*z(t)':eval=frame,crop=W:H:x=...:y=...`（先逐格縮放，再裁固定尺寸）。在 scale 後插 `showinfo` 確認縮放尺寸逐格變大（640×360 → 768×432 → … → 1536×864），crop 輸出固定 640×360。另一條路是 `zoompan` 搭配 `d=1`（未實測）。
- 注意：1080p 放大 4 倍再裁，CPU 每格要處理 7680×4320 的中間畫面，很重。這也是 A3 (b) 用 WebGL 做放大的理由之一。
- §5.19 的「`crop`＋`scale`」改成上面的寫法，順序要寫清楚。

### C2. 沙盒的 CSP 與隔離（§5.7、§5.15）

- `default-src 'none'` 會連沙盒自己的 Worker 都擋掉。要逐項寫明：`script-src blob:`（或 nonce）、`worker-src blob:`、`connect-src 'none'`、`img-src blob: data:`。
- srcdoc iframe 會繼承父頁的 CSP，Tauri 的 `app.security.csp` 也會套進來，兩邊要一起設計。
- Worker 裡沒有 `RTCPeerConnection`，但「iframe 主執行緒」退路與音效插件有；而且和主畫面同執行緒時，無窮迴圈殺不掉（§5.7 的「逾時直接終止」只對 Worker 成立）。
- 建議：AI 音效、AI 音樂改成輸出**宣告式 JSON**（振盪器、雜訊、濾波器、包絡、音符表），由我們的程式解讀並交給 `OfflineAudioContext`，不產 JS。無窮迴圈與外洩的風險一起消失，閘道也能用 schema 驗證。
- 可重現性：沙盒要覆寫 `Date.now`、`performance.now`、`Math.random`（改成固定種子），否則 §7「同一格兩次算出一樣」測不過。

### C3. 額度與預算算不攏（Q4、§6）

- AI 導演一次 30 分鐘素材、每秒 2 格，就是 3,600 格。若每格影片 token 數百，一次就逼近 1,000,000；§6 又說導演的 token「照樣計入」每日 LLM 額度，等於導演一次就吃光當日 LLM 額度。
- 建議：導演的 token 獨立計算（只算次數與單次上限），或明訂導演不計入 LLM 額度；10/27 量到每格 token 數後再校正。
- 全站每日 US$10～15，開發 9 天加評審 4 天共 13 天，是 US$130～195，可能超過 Meta 送的 US$150。建議加一個**全站累計上限**（例如 US$140 就停用 AI 路由），不只每日上限。

### C4. 評審的邀請權杖不要進公開 README（§5.22、§10）

只放在提交表；README 寫「評審權杖見提交表」。

### C5. 聲音分離只跑一個模型（§5.14）

- 背景音樂＝原音減人聲（UVR 的 secondary stem 作法），省掉 Inst_HQ_3。用作者先前的實測換算，19.2 秒音訊從約 141 秒降到約 46 秒，約 7 倍片長降到約 2.4 倍。
- 網頁版另用 onnxruntime-web 再做一份是重複實作，P1-10 又在砍除順序的前段。建議網頁版不做聲音分離，直接提示改用 Windows 版。

### C6. 字幕三邊一致（§5.4、§5.18）

預覽與網頁版匯出用 libass 的 WASM 版（例如 JASSUB）畫 ASS，和 Windows 匯出的 libass 一致。否則字型度量、斷行、`\kf` 卡拉 OK 效果在三個地方會不一樣。

### C7. 專案檔與資料模型（§3、§4）

- 遮罩逐格 RLE 塞在 `.wordblade.json`，每 2 秒自動存檔一次，檔案會很大。建議遮罩放旁檔 `masks/<id>.bin`，JSON 只存參照。
- 復原堆疊存快照要靠結構共享（例如 Immer），否則每次編輯都複製一份完整遮罩。
- `Media.path` 在網頁版沒有意義，要把 `FileSystemHandle` 存在 IndexedDB，重開時處理重新授權。
- `Track` 缺角色欄位（dialogue／music／sfx）：`sidechaincompress` 壓低配樂、聲音分離後新增的音樂軌都要靠它判斷。
- `Clip` 缺局部放大關鍵幀（§5.19）與定格（§5.20）的欄位。

### C8. 預覽音訊的變速（§5.13、§5.20）

變速又要保持音高，A 片段必須用 `<audio>`＋`MediaElementAudioSourceNode`，`preservesPitch` 才有作用；`AudioBufferSourceNode` 的 `playbackRate` 會連音高一起變。寫進 §5.13 的「聲音用 Web Audio 混」。

### C9. 詞級時間多一個來源（§5.2）

記憶庫的 Muse ASR 實測筆記（2026-09-16）提到 SSE `partialMode=DELTA` 可以拿到近似詞級的「發射時間」，§5.2 的詞級重建沒有用上。可以當成比音量包絡更準的第一來源，英文實測時一起量。
