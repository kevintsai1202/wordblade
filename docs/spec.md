## 1. 目標（報名內容）

講師用 OBS 錄課，整理成可上架的影片比錄影本身還花時間：改 ASR 聽錯的技術名詞、剪停頓與重講、對字幕時間、把臉、名牌、API 金鑰等不該出現的東西打馬賽克。WordBlade 是一個 Windows 桌面工具，把這些事一次做完：

1. Resolve 風格剪輯：漣漪時間軸、DaVinci Resolve 熱鍵、改逐字稿就剪片。
2. 快速字幕：詞級時間的逐字稿 → 依停頓與標點斷成好讀的字幕行（以英文為主）→ 直接改字 → 匯出 SRT 或燒錄。
3. 隱私遮罩：打字指定要遮的東西 → SAM 3.1 分割並跨格追蹤 → 馬賽克、模糊或純色，每個物件可以單獨開關。
4. AI 校稿：Muse Spark 對照講稿找出疑似聽錯的詞與重複語句，一鍵採用或略過（併進 AI 導演的建議清單，§5.5）。
5. 語音修補：用 Fish Audio 零樣本克隆自己的聲音，重唸講錯的一句（P2，§5.6）。
6. 匯出：MP4（硬體編碼）、SRT。（報名時列的 Final Cut Pro 7 XML 不做，D7。）
7. **素材庫＋多軌時間軸**（D14，報名後追加）：剪輯為主，多支影片、圖片、配樂、音效排在多條軌上；做不出來的效果用外部影片素材補。
8. **AI 導演**（D11，報名後追加）：Muse Wonder 統籌、Muse Spark 1.3 逐段看影片，產出剪輯建議清單，逐條採用。
9. 特效（D8、D17、D19，報名後追加，**核心**）：2D 與 3D（three.js）動畫插件、Vibe特效（用一句話讓 Muse Spark 寫出插件，3D 插件能和影片互動）、3D 場景（影片貼在桌上的螢幕等 3D 物件上，可以「用說的」控制鏡頭）、轉場。
10. **追加的剪輯功能**（D20）：一鍵去贅詞、發佈包、逐字高亮字幕與重配錄音卡拉 OK 模式、局部放大、片段變速、定格、轉場。

**成功標準**

- 用 WordBlade 從頭到尾剪完一支自己 30～60 分鐘的課：熱鍵剪輯、字幕、遮罩、輸出 MP4。
- 60 分鐘的課 5 分鐘內產生可剪輯的詞級逐字稿。
- SAM 遮罩在 60 秒片段中跟住目標，不需要手動關鍵幀。
- Demo 影片是 WordBlade 剪自己的宣傳影片（§9）。

## 3. 架構

```

│   素材庫／預覽／屬性／逐字稿＋導演清單／多軌時間軸                         │

│ 沙盒 iframe（無 same-origin、CSP 擋網路）                               │
│   Worker：2D Canvas／three.js 插件逐格畫  主執行緒：WebAudio 音效與配樂   │
│        │ invoke                                                       │
│ Rust 指令層：ffmpeg／ffprobe sidecar、檔案、背景工作、畫格管線、           │
│   聲音分離（ort＋rustfft，MDX-Net ONNX，DirectML／CPU）                  │
└────────┼──────────────────────────────────────────────────────────┘
         │ HTTPS（邀請權杖）
┌────────▼──────── WordBlade 閘道（Spring Boot 4.1＋Spring AI 2.0，Zeabur）──────┐
│ AI 任務（ChatClient＋結構化輸出＋Media＋ChatMemory＋@Tool）                     │
│   /v1/ai/director ──► Muse Wonder 統籌＋Muse Spark 1.3 逐段看影片            │

│   /v1/ai/image ──► Muse Image                                              │
│ 轉送（RestClient）：/v1/asr ──► Muse Voice Transcribe                       │
│   /v1/sam ──► SAM 3.1（上傳、SSE、刪檔）  /v1/tts ──► Fish Audio               │
```

- **提示詞在閘道**：桌面只送任務資料（逐字稿、描述、截圖、目前設定），拿回驗證過的結構化結果。提示詞與護欄要調整不必發新版桌面程式，也不會隨安裝檔流出。

- **兩個外殼、同一套程式（D21）**：介面、TS 核心、沙盒都只寫一份；和平台有關的部分（讀檔、轉代理檔、匯出、聲音分離、錄音）收在 `Engine` 介面後面，有 `DesktopEngine`（Tauri＋Rust）與 `WebEngine`（瀏覽器 API）兩個實作。
- **本機為主**：完整影片、剪輯與輸出都在本機。送出的只有 ASR 用的音訊，以及遮罩用的縮小、無聲片段（上傳前要使用者同意）。
- **專案檔** `<專案名>.wordblade.json`：素材庫、各軌片段、每支素材的逐字稿、字幕、遮罩、特效；素材只存路徑（代理檔放專案資料夾 `proxies/`）；復原歷史不存。
- **ffmpeg** 以 Tauri sidecar 打包。注意 **LGPL 版沒有 libx264**（x264 是 GPL）：LGPL 版有 NVENC／QSV／AMF 硬體編碼，沒有硬體編碼的電腦要用 OpenH264（BSD）或改打包 GPL 版。10/27 確認要用的 ffmpeg 版本有哪些編碼器，再決定（GPL 版的話，README 附 ffmpeg 原始碼取得方式）。
- **repo 授權**：提交前公開時選定（建議 Apache-2.0）；README 列出第三方授權（ffmpeg、three.js MIT、MDX-Net 模型 MIT、python-audio-separator MIT、MusicGen CC-BY-NC）。

| --- | --- | --- |

| `MaskObject` | id、mediaId、prompt、label、frames（每格的框與遮罩）、effect、enabled | 素材時間；遮罩跟著素材走，片段移到哪裡都套得上 |

## 5. 功能細節

### 5.1 剪輯與熱鍵

- 熱鍵照 DaVinci Resolve 預設鍵盤設定（開工時對照 Resolve 20 的鍵盤設定逐一核對）：J／K／L 倒退／停／前進（連按加速）、I／O 設入出點、Ctrl+B 在播放頭切割、漣漪刪除、← → 逐格、↑ ↓ 跳到上／下一個剪輯點、Ctrl+Z／Ctrl+Shift+Z 復原與重做、Space 播放。
- 漣漪時間軸：V1 刪掉的段落不留空隙；V2 以上與音軌可以自由擺放；拖曳片段、修邊、吸附到播放頭與片段邊界；時間軸上可以看到剪輯點，點了跳過去。
- 改字即剪：在逐字稿點選或拖選詞，按 Delete 就在對應片段的素材時間切開、刪掉中間（頭尾吸附到詞的邊界，前後各留 0.05 秒；V1 漣漪補位，同素材的 A 片段一起剪，§5.13）。
- 預覽：見 §5.13 的多軌合成預覽。

### 5.2 Muse ASR 字幕

已實測的事實（2026-10-14，三支中文錄課影片）：端點 `https://api.meta.ai/v1/asr/transcribe`；只收 WAV mono 16-bit 16／24 kHz、≤ 32 MB、≤ 10 分鐘；`PUSH_TO_TALK` 不回時間，`DIARIZATION` 才有 turn 級 `startMs／endMs`；有 `keywords` 偏向術語；554 秒影片約 89 秒；轉出的稿子與參考稿的接近程度不輸 Groq Whisper turbo。英文影片還沒實測，10/29 開工時先跑一支。

流程：

1. ffmpeg 抽 16 kHz mono WAV；在靜音處切成 ≤ 9 分鐘的段（每段 < 32 MB）。
2. 每段帶 `keywords`（講稿抽出的術語）經閘道送出，最多 3 段平行。
3. 詞級時間重建：
   - 用音量包絡找出有聲段（RMS 門檻＋最短靜音 0.25 秒）。
   - 每個 turn 的文字切成詞（英文以空白分詞、標點黏在前一個詞；中文逐字），依有聲段的長度按字元數比例分配時間。
   - 詞的頭尾吸附到實際開口與收尾。
   - 精度不夠的話，升級路徑是 Meta 開放權重的 MMS forced aligner（P2 以後）。
4. 不做簡轉繁：ASR 回什麼文字就用什麼（D7）。
5. 字幕斷句（以英文為主）：
   - 先斷句：句末標點（`.` `?` `!`）或停頓 ≥ 0.5 秒。
   - 一句太長再斷行：每行最多 42 個字元、最多 2 行；優先斷在逗號、分號、冒號之後，其次斷在連接詞（and、but、so、because…）與介系詞之前；不讓冠詞、介系詞留在行尾，不拆開數字與單位。
   - 每段字幕最短 1 秒、最長 7 秒；閱讀速度上限每秒 17 個字元，超過就延長顯示或拆段。
   - 中文內容照樣能轉錄與上字幕，用同一套規則（行長改以全形字計），不另外調。
6. 驗收：用自己的英文錄影（至少 2 支）量「詞的起點和人工標的起點」平均誤差，目標 ≤ 0.15 秒；字幕抽 50 段人工看，斷在不自然位置的 ≤ 10%。

### 5.3 SAM 3.1 遮罩（P1-5）

1. 使用者輸入要遮的東西（例如「我的臉和桌上的名牌」）。P1 由 Muse Spark 轉成英文名詞片語（`face`、`name badge`）；P0 先讓使用者直接打英文。
2. 選範圍後，Rust 層用 ffmpeg 剪出縮小、無聲的片段（寬 ≤ 1280、每秒 10 格），上傳前顯示同意對話框。
3. 閘道上傳到 Meta、呼叫 SAM 3.1 影片追蹤、把逐格結果（框＋RLE 遮罩）以 SSE 轉回、結束後刪檔。
4. 換鏡頭處切段（ffmpeg `scdet`），同一個物件不跨鏡頭配對，避免遮罩借到另一個鏡頭。
5. 物件清單：每個物件一列，可開關、選效果（馬賽克、模糊、純色）與強度。
6. 預覽：遮罩屬於素材（素材時間），哪一軌放了這支素材的片段，就在那個片段的畫面上用 canvas 畫效果；輸出時同一份遮罩轉成 ffmpeg 的遮罩影片（alphamerge＋overlay），在該片段疊進合成之前套上，兩邊一致。
7. 費用：SAM 影片 US$0.20／千格；每秒 10 格時 1 分鐘約 US$0.12。

### 5.4 MP4 匯出

- 多軌合成：V1 各片段 `trim`＋`concat`；V2 以上用 `overlay`（依片段時間 `enable`、子母畫面先 `scale`、透明素材保留 alpha、淡入淡出用 `fade=alpha=1`）；音軌各片段 `atrim`、`adelay` 後 `amix`，配樂在有人講話的區間用 `sidechaincompress` 壓低；變速用 `setpts`＋`atempo`。硬體編碼依序試 `h264_nvenc`、`h264_qsv`、`h264_amf`，都不行用 `libx264`。
- 片段多時濾鏡圖會很大：輸入超過 8 個就先把每條疊加軌各自預算成一支中間檔再合成（記憶體與速度都比一張大圖好）。
- 2D／3D 插件與 3D 場景：照 §5.7 的畫格管線算好再疊進合成，順序照 §5.10。
- 字幕寫成 ASS 燒錄（字型、描邊、底色可調三種預設），在最上層。
- 匯出進度由 Rust 層讀 ffmpeg `-progress` 回報；可取消。
- 同時輸出 SRT（剪後時間）。

### 5.5 校稿（併進 AI 導演）

校稿候選是 AI 導演建議清單的一種（§5.11）；做法如下，由 Muse Spark 1.3 分批做。

- 桌面把逐字稿分批（約 400 字一批）送到閘道 `/v1/ai/proofread`；閘道用 `ChatClient` 的結構化輸出拿回疑似聽錯的詞（位置、建議文字、理由代碼）與重複語句（範圍），驗證位置在範圍內再回給桌面。
- 有講稿時一起送，當成術語與原句的參考。
- 介面：候選清單，Enter 採用、Esc 略過，採用即改逐字稿與字幕。

### 5.6 AI 重生語音（P2，D18）

- 選一段字 → 取那段前後的**人聲**當聲音樣本（有做聲音分離時用分離後的人聲，樣本不混音樂）→ 閘道 `/v1/tts` 轉 Fish Audio 生成 → 調整長度對齊原區間 → 產生一個新的音訊片段放在原位置，原本那段人聲靜音；背景音樂軌不受影響。
- Meta 沒有 TTS（模型清單已確認），所以用 Fish Audio；供應商包在閘道後面，之後可換。

### 5.7 動畫插件與 Vibe特效（P0 核心，2D 與 3D，D19）

- **2D 插件**：一段 JS，匯出 `render(ctx, t, params, env)`，在透明畫布上畫一格；可以附短音效（Web Audio 合成）。
- **3D 插件（D17）**：一段 JS，匯出 `setup(THREE, scene, camera, env)` 建場景、`update(t, env)` 每格更新；three.js 由我們打包進沙盒（不從網路載），模型對 three.js 很熟，寫起來比自訂 API 可靠。可以只畫疊加物件（透明背景），也可以畫整個畫面（例如影片貼在桌上的螢幕）。
- **`env`（唯讀，2D 與 3D 共用）**——插件和影片互動靠這些：
  - 畫面尺寸、時間、區段長度、使用者框的目標框。
  - **當格畫面**：每格傳一張 ImageBitmap；3D 插件可以拿來當貼圖（例如貼在螢幕上），2D 插件可以取色、找亮處。
  - **定位點**：SAM 找到的物件框、AI 導演標出的位置、使用者在畫面上點的點（吉祥物可以走過去指著它）。
  - **逐字稿與音量**：這個區段的詞與時間、每格的人聲音量（講到關鍵字時做動作、跟著音量點頭）。
  - 固定種子的亂數（同一格每次算出來都一樣，預覽與輸出一致）。
- **可重現規則**：畫面只能由 `t` 與 `env` 決定。插件若在 `update` 之間累積狀態（例如物理模擬），預覽跳到別的時間時沙盒會從區段開頭重跑 `setup` 並逐格推到目標時間；輸出一律從區段開頭依序算，所以結果和從頭播放的預覽相同。
- **沙盒**（Q6）：插件在 `sandbox="allow-scripts"`（不給 same-origin）的 iframe 裡的 Worker 執行（3D 用 OffscreenCanvas 的 WebGL2）；CSP `default-src 'none'`；只能用我們給的 API 與 three.js；每格限時（2D 30 ms、3D 100 ms），單段最長 60 秒；逾時直接終止 Worker。存檔前先試跑一次。10/27 實測：沒有 same-origin 的 iframe 能不能建 Worker（blob URL）、Worker 裡的 WebGL2；不行就在 iframe 主執行緒跑，隔離一樣靠 iframe。
- **範本**：2D——框線強調、箭頭、打勾、聚光燈、文字彈出、粒子、計數器、打字機。3D——螢幕在桌上（§5.8）、吉祥物（基本幾何組成，會走路、揮手、指東西）、3D 箭頭、彩帶、浮起的 3D 標題。模型從零寫的品質不穩，所以 Vibe特效預設拿最接近的範本當底稿修改。
- **外觀參考**：可以先用 Muse Image 畫概念圖（例如吉祥物），再附給 Muse Spark 當參考圖寫 3D 幾何；也可以匯入現成的 glTF（.glb）模型當素材，模型只寫動作。
- **Vibe特效**：使用者輸入一句描述（可附當格截圖）→ 閘道 `/v1/ai/vibe` 用 `ChatClient`（截圖用 `Media`）請 Muse Spark 回結構化結果（插件程式＋參數定義）→ 桌面沙盒試跑；語法錯、執行錯、逾時就帶同一個對話 id 把錯誤送回閘道，閘道用 `ChatMemory` 接續同一段對話請模型重寫，最多 3 輪。描述與截圖當不可信資料；只准產生畫面動畫與音效，其他要求回拒答代碼，介面不顯示模型寫的自由文字。是不是特效需求、有沒有越獄或要連網，由 Muse Spark 在同一次呼叫裡判斷並回拒答代碼（D9，不另外用分類模型）。
- **輸出**：同一個 Worker 依時間逐格畫，畫格（RGBA）由 Rust 層用管線直接餵給 ffmpeg（`-f rawvideo`），疊回合成；需要當格畫面時，Rust 先把那段合成畫面解成畫格送進沙盒。音效算成 WAV 混進去。只算有插件的區段。
- **畫格傳輸量**：1080p 一格 RGBA 約 8 MB，30 fps 等於每秒雙向各 240 MB。10/27 實測 Tauri IPC（二進位回應）的速度；不夠就：3D 圖層用 720p 算再放大、或在沙盒裡用 WebCodecs 直接解代理檔取當格畫面（省掉送進去的那一半）。

### 5.8 3D 場景與「用說的」（P0 核心，three.js，D19）

- 「平面轉 3D」改成 three.js 的內建 3D 範本（D17），影片畫面當貼圖貼在 3D 物件上：
  - **螢幕在桌上**：木紋桌上平放或立起一塊螢幕，播這段影片；仿之前 YT 宣傳影片的場景。
  - **漂浮的板子**：板子在空間中轉動、推近、拉遠（原本平面轉 3D 的效果）。
  - **教室黑板**、**攝影棚**：背景換成不同場景。
- **鏡頭關鍵幀**：位置、看向的點、視角；錨定區段開頭或結尾；頭尾可以自動接回滿版平面。鏡頭跟著定位點移動（例如跟著畫面上被點的按鈕）。
- 背景：內建場景、模糊原畫面、純色、自訂圖、Muse Image 產生的圖（§5.12）。
- 範本本身就是一個 3D 插件，可以再疊吉祥物等 3D 物件，也可以交給 Vibe特效修改。
- **用說的**：一句描述（可附當格截圖）→ 閘道 `/v1/ai/plane3d` 用結構化輸出拿回鏡頭關鍵幀與場景設定（不是程式碼）→ 閘道驗證範圍與時間順序（不合格回饋重問一次）→ 桌面進入 AI 預覽，按「套用」才寫進專案。要改物件或動作時改走 Vibe特效。
- 字幕、2D 動畫、疊加軌不跟著 3D 場景轉，留在上層。
- 輸出照 §5.7 的 3D 插件：逐格算、管線餵 ffmpeg。

### 5.9 轉場（P2）

- 在剪輯接點加轉場：溶接、穿黑、穿白、推移、推近；長度可調。
- 接點兩側沒有多餘畫面（手把）時，用兩側的最後／第一格定格補。
- 預覽用兩個 `<video>` 交疊；輸出用 ffmpeg `xfade`（注意每個實例吃記憶體，段數多時逐段預算）。

### 5.10 疊放順序

B-roll 已併進多軌時間軸的疊加軌（D13、§5.13）。預覽與輸出相同，由下到上：

V1 主軌 → 3D 場景（把下面的合成當貼圖）→ V2、V3…疊加軌（子母畫面、外部做的透明素材）→ 2D／3D 動畫插件 → 字幕。遮罩跟著素材，先套在各自的片段上（§5.3）。

### 5.11 AI 導演（P1-1；核心 Vibe特效之後的第二亮點）

**目標**：使用者開一支錄影、按「Ask the director」，幾分鐘後拿到一份剪輯建議清單，逐條按 Enter 採用、Esc 略過。

**模型分工（D12）**

| 角色 | 模型 | 做什麼 |
| --- | --- | --- |
| 統籌 | Muse Wonder（`muse-wonder-1.0`，推理深度 medium） | 看全片摘要與各段報告，決定整體剪輯方向（節奏、哪幾段最重要、哪裡值得加特效），呼叫工具產生具體建議，最後去重、排序、寫每條的一句理由 |
| 苦工 | Muse Spark 1.3（`muse-spark-1.3`，推理深度 low） | 逐段（約 2 分鐘一段）看縮小的影片＋那段逐字稿，回結構化報告：重講與口誤、畫面上的隱私資訊（臉、Email、API 金鑰、名牌）與時間、適合強調的時刻；也負責校稿、寫動畫插件、產生 3D 關鍵幀 |

- 使用者內容一律用 Standard 模式（不用 Contributor 模式：它的內容可能拿去訓練模型）。
- Muse Spark 1.3 的音訊理解官方標註不完整，所以聲音的部分改給逐字稿文字，影片只送畫面（無聲）。

**流程**（以素材為單位：對素材庫裡一支有聲音的影片執行；要先有逐字稿，沒有就先自動跑 Muse ASR）

1. 桌面把影片縮成約 480p、每秒 2 格、無聲，依逐字稿的停頓切成約 2 分鐘一段；連同逐字稿送到閘道 `/v1/ai/director`（非同步工作，SSE 回報進度）。
2. 閘道把各段平行交給 Muse Spark 1.3（最多 4 段同時），拿回每段的結構化報告。
3. Muse Wonder 拿到全片摘要與各段報告，透過 Spring AI 的工具呼叫（`@Tool`）產生建議：
   - `proposeCut(start, end, reason)`：重講、口誤、太長的停頓。
   - `proposeMask(start, end, target)`：隱私項目；`target` 轉成 SAM 的名詞片語。
   - `proposeEffect(start, end, description)`：要加的動畫，`description` 之後交給 Vibe特效。
   - `proposeCamera(start, end, description)`：要加的 3D 運鏡，之後交給「用說的」。
   - `proposeFix(wordId, text)`：聽錯的詞（校稿）。
   - `proposeZoom(start, end, region)`：畫面上正在操作的地方，建議局部放大（§5.19）。
4. 閘道驗證每條建議（時間在片長內、不重疊、數量上限），回給桌面。
5. 桌面清單依時間排列（素材時間，換算到用到這支素材的片段），點一條跳到那個時間並預覽效果；採用時：剪輯就切開並刪掉那段、遮罩呼叫 SAM、特效呼叫 Vibe、運鏡呼叫 3D、改字直接改逐字稿。每次採用一次 snapshot，可 Ctrl+Z。

**驗收**：用自己的一支 20～30 分鐘錄影，建議清單裡人工判斷「有用」的比例 ≥ 60%；隱私項目（事先在畫面放一個假 API 金鑰）要被找到。

**第一天要實測**：Muse Spark／Wonder 影片輸入的上限（大小、長度、要不要先用 Files API 上傳）、每段的耗時與費用、Muse Wonder 工具呼叫在 Spring AI 2.0 下能不能用。任何一項不行就退回：全部由 Muse Spark 1.3 做、Wonder 只負責最後整理清單。Spring AI 的 OpenAI 模組不一定會把影片 `Media` 轉成 Meta 要的格式（今天只證實圖片可以）：不行就改送每段的關鍵格圖片（每 2～3 秒一張），或那一支呼叫改用 `RestClient` 直接打。

### 5.12 Muse Image（P2）

- **3D 背景**：輸入一句描述（例如「a cozy classroom with a chalkboard」）→ Muse Image 產生背景圖，存進專案當 3D 的自訂背景。
- **影片縮圖**：從成片挑一格當底圖，加標題文字的需求 → Muse Image 編輯成 YouTube 縮圖（1280×720）。
- 走閘道 `/v1/ai/image`，計入每日額度（張數）。

### 5.13 素材庫與多軌時間軸（P0）

**素材庫**

- 匯入：拖放或選檔，影片、圖片、音樂、音效都可以；ffprobe 讀規格，產生縮圖、波形；需要時在背景產生代理檔（Q5），完成前片段顯示「準備中」。
- 每支有聲音的影片可以各自跑 Muse ASR、AI 導演、SAM；結果存在那支素材上。
- 拖到時間軸：影片到 V 軌，**聲音直接分離**成 A 軌上獨立的片段（D15：兩者不連動，可以各自移動、修邊、刪除）；圖片到 V 軌（預設 5 秒）；音樂與音效到 A 軌。
- 改字即剪與 V1 的漣漪刪除：同時剪掉同一個時間範圍內、來自同一支素材的 A 片段，影音才不會錯開；其他情況影音各自獨立。

**軌道**

- V1 主軌：片段首尾相接，漣漪剪輯。
- V2 以上：疊加軌，可以有空隙；片段可設全畫面或子母畫面（在預覽上拖曳調框）、透明度、淡入淡出；帶透明的素材（例如外部做的 3D 吉祥物動畫）直接疊上。
- A 軌：A1 放分離出來的主音（講話）；A2 配樂（循環、淡入淡出、有人講話時自動壓低）；A3 音效。每軌與每段可調音量、靜音。

**介面（D15）**

- 單一畫面，所有區塊同時顯示：左上素材庫、中間預覽、右上屬性面板（選取中的片段或特效的設定）、右側逐字稿與 AI 導演清單、下方多軌時間軸。
- 不做區塊收放、不做模式切換；區塊之間的分隔線可以拖曳調大小就好。
- 力求功能完整：每個功能都能從這個畫面直接操作，不藏在子頁裡。

**合成預覽**

- V1 用兩個 `<video>` 交替播放（下一段預先載入），切換時不閃黑；V2 以上每個可見片段一個 `<video>`／`<img>`，依片段的框與透明度擺放；全部跟著同一個主時鐘同步（偏差超過 1 格就校正）。
- 聲音用 Web Audio 混：每個片段一個來源節點，配樂壓低在預覽也照算。
- 3D、動畫、字幕照 §5.10 的順序疊在上面。

**做不出來的效果用素材補（D14）**

- 例如 3D 吉祥物走動、真 3D 場景：在外部（three.js、Blender 等）做成帶透明的影片（ProRes 4444 或 VP9 透明 WebM），匯入素材庫放到疊加軌。
- 這是剪輯軟體的正常用法；demo 影片裡用到的外部素材在 README 註明來源。

### 5.14 聲音分離：人聲／背景音樂（P1-10，D16）

**目標**：一支素材的聲音拆成「人聲」與「背景音樂」兩個獨立片段，各自調音量、剪輯、靜音；例如去掉原片的音樂換成自己的配樂，或只留音樂。

**模型**（本機執行，不上傳）

| 模型 | 輸出 | 授權 |
| --- | --- | --- |
| Kim_Vocal_2（MDX-Net ONNX，約 64 MB） | 人聲 | MIT（UVR 隨附，KimberleyJensen 訓練） |
| UVR-MDX-NET-Inst_HQ_3（MDX-Net ONNX，約 64 MB） | 背景音樂 | MIT（UVR 開發者 Anjok07、aufr33 訓練） |

- 推論做法參考 python-audio-separator（MIT）：STFT → ONNX 推論 → iSTFT，分段處理並重疊接合；在 Rust 層用 `ort`（onnxruntime）＋`rustfft` 實作，Windows 先試 DirectML（內顯），不行退回 CPU。README 與關於頁列出兩個模型與 python-audio-separator 的授權。
- 已知速度（作者先前實測，CPU）：19.2 秒的音訊，人聲模型約 46 秒、音樂模型約 95 秒；DirectML 會快很多。長片在背景跑、顯示進度、可取消；結果依「素材＋模型」快取在專案的 `stems/`，不重算。
- 模型檔不放進 repo：第一次用時下載到使用者資料夾並驗 SHA-256（安裝檔不必大 130 MB）。

**介面與時間軸**

- 素材庫或 A 片段的右鍵選單「Separate vocals / music」。
- 完成後，原本的 A 片段換成兩個片段：人聲留在原軌（A1），背景音樂放到新增的一條 A 軌，位置、修邊與原片段相同；兩者不連動（D15）。
- 分離後的人聲有三個額外用途：
  - Muse ASR 改送人聲（背景音樂不干擾，辨識更準）。
  - 配樂自動壓低的「有人講話」判斷改看人聲的音量。
  - AI 導演的逐段分析一樣用人聲的逐字稿。

**輸出**：人聲與背景音樂就是兩個普通的音訊素材（WAV），匯出照一般的多軌混音處理。

**三軌拆分（人聲／音樂／音效）與 Demucs：先實測（D18）**

- MDX-Net 只分得出「人聲」與「其他」，原片內嵌的音效會跟音樂混在一起。
- 10/27 實測兩件事：
  1. Meta 的 Demucs（`htdemucs`，MIT）：人聲品質和 MDX-Net 比，以及能不能在 Rust 用 ONNX 跑（或改在 Modal／Baseten 上跑）。換成 Demucs 就多用一個 Meta 開放權重模型。
  2. 找得到能分出「對白／音樂／音效」的開放模型就試；分得出來才做第三軌（音效放到另一條 A 軌）。
- 兩項都不理想就維持 MDX-Net 兩軌，不影響其他功能。

### 5.15 AI 音效與 AI 音樂（D18）

**AI 音效（P1-8）**

- 一句描述（例如「whoosh」「keyboard typing」「pop」）＋長度 → 閘道 `/v1/ai/sound` 請 Muse Spark 寫 WebAudio 合成程式（只准用振盪器、雜訊、濾波器、包絡、效果器，不准載入外部檔）→ 桌面沙盒用 `OfflineAudioContext` 算成 WAV → 進素材庫，可以直接拖到 A3 音效軌。
- `OfflineAudioContext` 不能在 Worker 裡用，所以音效在沙盒 iframe 的主執行緒算（隔離一樣靠 iframe 沙盒與 CSP）。
- 和動畫插件的音效同一套沙盒與護欄；內建 8～10 個範本（whoosh、pop、ding、打字、上升音、下降音、點擊、轉場掃頻…）當模型的底稿。

**AI 音樂（P1-11，WebAudio 版）**

- 一句描述（風格、速度、情緒）＋長度 → 閘道 `/v1/ai/music` 請 Muse Spark 寫一段 WebAudio 的配樂程式（和弦進行、節奏、旋律；要能無縫循環）→ 沙盒算成 WAV → 素材庫、A2 配樂軌。
- 音色偏合成器，適合當科技類影片的背景配樂；可以「再生成一次」或「改一下」（帶著前一版程式修改）。

**AI 音樂（P2，Meta MusicGen）**

- Meta AudioCraft 的 MusicGen（開放權重）部署在 Modal 或 Baseten（黑客松合作夥伴各送 100 美元額度），閘道 `/v1/music` 轉送：描述＋長度 → 音樂 WAV。
- 品質比 WebAudio 版好很多，也多用一個 Meta 開放權重模型；但**權重授權是 CC-BY-NC 4.0（非商用）**，只限黑客松展示，之後商品化要換掉。
- 約 1 天（部署＋轉送），P1 都完成才做。

### 5.16 一鍵去贅詞（P1-4，D20）

- 贅詞清單：英文 um、uh、erm、ah、hmm；中文 呃、嗯、欸。「like」「you know」「那個」「就是」這類有時是正常用詞，預設不勾，使用者可以加進清單。
- 從逐字稿找出贅詞 → 列表（每條可試聽）→ 「Remove all」一次剪掉（同改字即剪：切開、刪掉、V1 漣漪補位），一次 snapshot 可 Ctrl+Z。
- **ASR 可能不寫出贅詞**（很多 ASR 會自動略過）：10/31 用英文錄影實測 Muse ASR 有沒有保留。沒有的話，改從聲音找：兩個詞之間有聲音、卻沒有對應文字的短片段（0.15～1 秒），列為「疑似贅詞」，一樣讓使用者試聽確認。
- AI 導演的 `proposeCut` 也會把明顯的贅詞與口吃列進建議。

### 5.17 發佈包（P1-7，D20）

- 剪完後按「Publish kit」：閘道 `/v1/ai/publish` 把成片的逐字稿（換算成成片時間）交給 Muse Spark，結構化輸出：
  - 3 個標題選項、影片說明（含重點條列）、章節（`0:00 Intro` 格式，時間對應成片）、標籤。
- 縮圖：從成片挑一格（或使用者指定）＋標題文字 → Muse Image 編輯成 1280×720 縮圖（§5.12）。
- 匯出：`publish.md`（標題、說明、章節、標籤）與 `thumbnail.png` 和 MP4 放在同一個資料夾；介面有「複製」按鈕可直接貼到 YouTube。

### 5.18 逐字高亮字幕與重配錄音卡拉 OK 模式（D20）

**逐字高亮字幕（P1-3）**

- 字幕樣式多一個「Karaoke」：目前講到的詞變色（或放大、加底色），用 §5.2 重建的詞級時間。
- 預覽：字幕層每格依詞的時間更新；輸出：ASS 的 `\kf` 卡拉 OK 標籤（逐字填色）或逐詞拆成多個事件（放大效果），預覽與輸出一致。
- 幾種預設：黃色填色、整詞放大、底色塊跳動；可調顏色與字型。

**重配錄音卡拉 OK 模式（P1-9）**

- 用途：某段講錯、或想重講得更好，又要和原本的節奏、畫面對得上。
- 流程：在逐字稿選一段字 → 按「Re-record」→ 提詞器全螢幕顯示這段字，倒數 3 秒後**照原本的時間逐字高亮**（像卡拉 OK），播原畫面（原聲靜音或小聲）→ 使用者跟著念，麥克風同步錄音 → 錄完可以試聽、重錄。
- 套用：新錄音變成 A 軌上的一個片段放在原位置，原本那段人聲靜音；長度差 ±15% 內自動用 `atempo` 對齊原長度，超過就提示。
- 提詞器的字可以先改（例如改掉講錯的字），高亮時間照原本的詞時間按字數比例分配。
- 麥克風：WebView2 的 `getUserMedia`，Tauri 要設定權限；10/27 骨架時先確認錄得到（作者先前在公司電腦遇過防毒擋錄音，換電腦或改由 Rust 層錄音是備案）。
- 和 AI 重生語音（§5.6，P2）是兩種選擇：自己念，或讓 AI 用你的聲音念。

### 5.19 局部放大（P1-2，D20）

- 片段層級的縮放與平移關鍵幀：每個關鍵幀記放大倍率（1～4 倍）與中心點，關鍵幀之間用緩動；可以設多個關鍵幀讓畫面沿路徑移動（例如跟著滑鼠游標）。
- 操作：在預覽上拖一個框＝這個時間點要看的範圍；播放頭移到別的時間再拖一次＝新的關鍵幀。頭尾自動加 0.5 秒平滑進出。
- 預覽：CSS transform 套在那個片段的畫面上；輸出：ffmpeg `crop`＋`scale`（中心與倍率寫成依時間的運算式），預覽與輸出共用同一份 TS 的內插函式。
- AI 導演多一個工具 `proposeZoom(start, end, region)`：Muse Spark 看到畫面上正在操作的地方（游標、正在打字的區域）就提議放大。
- 和 3D 場景的順序：局部放大在片段上先做，3D 場景拿放大後的畫面當貼圖。

### 5.20 片段變速、定格與其他特效（D20）

- **片段變速（P1-6）**：屬性面板設 0.25～4 倍；畫面 `setpts`、聲音 `atempo`（保持音高，超過 2 倍時串接多個 `atempo`）；時間軸上片段長度跟著變；預覽用 `<video>.playbackRate`＋`preservesPitch`。
- **定格（P2）**：在播放頭把畫面凍結 N 秒（插入一個靜止片段，聲音可選靜音或繼續），常用在講解時停在某個畫面。
- **轉場（P2）**：見 §5.9。
- **色彩調整（P3）**：片段層級的亮度、對比、飽和度、色溫；ffmpeg `eq`＋`colortemperature`，預覽用 CSS filter。
- 其他畫面特效（強調框、箭頭、大標、字卡、粒子…）一律由 2D／3D 插件與 Vibe特效提供，不另外寫成內建功能。

### 5.21 網頁版與效能（P0，D21）

**效能原則（只有 CPU）**

- **預覽一律用低解析代理檔**：每支影片匯入時產生 540p（寬 960）的 H.264 代理檔，關鍵幀間隔短（1 秒），預覽、拖曳、逐格都用它；CPU 解碼 1080p 太吃力。匯出才用原檔。
- **重運算走原生（Windows 版）**：ffmpeg 多執行緒（`-threads` 依核心數）；有 Intel 內顯時用 QSV 解碼與編碼，沒有就 libx264（授權見 §3）；聲音分離用 onnxruntime 原生 CPU 多執行緒，有 DirectML 再用。
- **AI 分析都在雲端模型**（ASR、AI 導演、SAM、Vibe），不吃本機。
- **重工作排隊**：代理檔、聲音分離、匯出一次只跑一個，避免互搶 CPU；進度條顯示排隊順序。
- **3D**：WebGL 用內顯即可。偵測到沒有硬體加速（軟體算繪）時，3D 預覽自動降到 540p、匯出的 3D 區段用 720p 算再放大，並提示使用者。
- **10/27 在實際的 CPU 電腦上量**：(1) 10 分鐘多軌時間軸用 ffmpeg 匯出要多久；(2) 同一段用 WebCodecs 匯出要多久；(3) 5 秒 3D 區段的畫格從沙盒交給 ffmpeg 要多久（直接傳 RGBA、或在沙盒先壓成 PNG）。依結果定 Q7 的細節。

**網頁版**

| 項目 | 網頁版 | Windows 版 |
| --- | --- | --- |
| 執行環境 | Chrome／Edge（WebCodecs、File System Access、OPFS） | Tauri 2（WebView2） |
| 匯入格式 | 只吃 H.264／AAC 的 MP4、MOV（瀏覽器能解的）；其他格式提示用 Windows 版 | 任何 ffmpeg 讀得到的格式，非 H.264 先轉代理檔 |
| 代理檔 | 用 WebCodecs 轉 540p（較慢）；短片可以直接用原檔 | ffmpeg |
| 匯出 | WebGL 合成＋WebCodecs 編碼（H.264；有 AAC 編碼器用 AAC，沒有用 Opus）＋mediabunny 封裝 MP4 | ffmpeg（Q7） |
| 聲音分離 | onnxruntime-web（WASM 多執行緒，CPU 很慢）：只開放 ≤ 3 分鐘的片段，並提示「長片請用 Windows 版」 | onnxruntime 原生 |
| 麥克風錄音 | `getUserMedia` | 同左 |
| 建議片長 | ≤ 10 分鐘 | 不限 |

- 部署：靜態網站放在 Zeabur 的 `wordblade` 專案（和閘道同一個專案），網址例如 `wordblade.zeabur.app`；閘道要開放這個網域的 CORS。
- WebCodecs、OffscreenCanvas、File System Access 需要的安全標頭（COOP／COEP，用來開 WASM 多執行緒）一起設好。
- 伺服器沒有 GPU，所以 MusicGen、Demucs 這類要 GPU 的模型不能放 Zeabur，只能用 Modal／Baseten（合作夥伴額度）或不做。

### 5.22 範例專案、一鍵試用（P0，D22）

## 6. 閘道

- **技術**：Java 21、Spring Boot 4.1、Spring AI 2.0、PostgreSQL（Flyway）；部署在 Zeabur。報名稿寫的就是這個架構（D10）。
- **AI 任務路由**（Spring AI `ChatClient`，OpenAI 相容；統籌用 Muse Wonder、其他用 Muse Spark 1.3，D12）：

| 路由 | 輸入 | 輸出（結構化，Java record） | 用到的 Spring AI 功能 |
| --- | --- | --- | --- |
| `POST /v1/ai/proofread` | 一批逐字稿、選用講稿 | 疑似聽錯的詞、重複語句 | `.entity()` 結構化輸出 |
| `POST /v1/ai/vibe` | 種類（2d／3d）、描述、選用截圖與參考圖、畫面條件、底稿範本；續修時帶對話 id 與錯誤 | 插件程式＋參數定義，或拒答代碼 | 結構化輸出、`Media`、`ChatMemory` |
| `POST /v1/ai/plane3d` | 描述、選用截圖、區段長度、目前場景與鏡頭關鍵幀、定位點 | 鏡頭關鍵幀與場景設定（不是程式碼），或拒答代碼 | 結構化輸出、`Media`、驗證不過回饋重問 |
| `POST /v1/ai/mask-terms` | 任何語言的遮罩描述 | 1～4 個英文名詞片語 | 結構化輸出 |
| `POST /v1/ai/director` | 縮小的分段影片、逐字稿 | 建議清單（非同步工作，SSE 回進度） | Muse Spark 1.3 平行逐段分析＋Muse Wonder 工具呼叫（`@Tool`）統籌 |
| `POST /v1/ai/image` | 背景描述，或縮圖底圖＋標題 | 圖片 | Muse Image（`/v1/images/generations`、`/edits`） |
| `POST /v1/ai/sound` | 音效描述、長度；改版時帶前一版程式 | WebAudio 合成程式（桌面沙盒算成 WAV），或拒答代碼 | 結構化輸出 |
| `POST /v1/ai/music` | 配樂描述（風格、速度、情緒）、長度；改版時帶前一版程式 | 可循環的 WebAudio 配樂程式，或拒答代碼 | 結構化輸出 |
| `POST /v1/ai/publish` | 成片逐字稿（成片時間）、片長 | 標題選項、說明、章節、標籤 | 結構化輸出 |

  開工第一天先實測 Muse Spark 支不支援 `json_schema` 結構化輸出；不支援就改用 JSON 模式＋Spring AI 的輸出轉換器解析，失敗算一輪、回饋重問。

- **轉送路由**（`RestClient`，Spring AI 沒有對應的模型介面）：

| 路由 | 上游 | 計量 |
| --- | --- | --- |
| `POST /v1/asr` | Muse Voice Transcribe | 音訊秒數（WAV 長度） |
| `POST /v1/sam` | SAM 3.1（上傳、SSE 轉送、刪檔） | 影片格數 |
| `POST /v1/tts` | Fish Audio | 生成語音秒數 |
| `POST /v1/music` | Meta MusicGen（Modal／Baseten 上的端點，P2） | 生成音樂秒數 |
| `GET /v1/me` | — | 今日用量與上限 |

  AI 任務路由的 LLM 用量（輸入＋輸出 tokens）照樣計入每人每日額度；AI 導演另計次數、Muse Image 計張數（Q4）。

- **驗證**：`Authorization: Bearer <邀請權杖>`；權杖只存 SHA-256；可停用。
- **額度**：每人每日（Q4）＋全站每日總量；用完回 403 `daily-limit`（不用 429，避免客戶端自動重送）。
- **CORS**：只開放網頁版的網域（D21）；Windows 版不帶 Origin。
- **費用保護**：Meta 的黑客松額度（US$150）用完會開始扣作者的卡，全站每日總量上限抓在每天 US$10～15（依各模型單價換算成 token、格數、張數）。
- **安全**：金鑰只在閘道環境變數；log 不記內容、只記用量；不回傳供應商錯誤內容；請求大小與逾時上限。
