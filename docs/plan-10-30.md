# 10/30 開發計畫：核心②（3D 插件、3D 範本、用說的、Vibe特效 3D）

依據：`docs/spec.md` §5.7（3D 插件）、§5.8（3D 場景與用說的）、§5.10（疊放順序）；10/27 晚上提前開始。
開發者 2026-10-27 決定：
- **運鏡資料兩種並存**：「漂浮的板子」沿用原專案（字導字演）的板子姿勢關鍵幀（rx、ry、rz、size、px、py，數學、5 個範本、「用說的」AI 都實測過）；桌上螢幕、教室、吉祥物這類 3D 場景用 spec 的鏡頭關鍵幀（位置、看向、視角）。
- **場景素材用 three.js 程式畫**（木紋、黑板用程式產生的貼圖）：沒有授權問題、鏡頭可以繞著走、不佔安裝檔；原專案 Muse 生成的 desk／board 圖商用條款待確認，不沿用。

## 沿用

| 原專案 | WordBlade | 做法 |

| CSS matrix3d／ffmpeg perspective 的畫法 | 不沿用 | 改成 three.js 在沙盒 Worker 裡畫（預覽與匯出同一條路，D24） |

## 任務

| # | 任務 | 驗收 |
| --- | --- | --- |
| ① | 沙盒加 3D Worker：three.js 打包成一段原始碼（Vite 外掛＋esbuild，不放進主程式）；3D 插件契約 `setup(THREE, scene, camera, env)`／`update(t, env)`，harness 管 WebGLRenderer（OffscreenCanvas、透明背景）、當格畫面貼圖（`NoColorSpace`）、固定亂數與時間；跳格時從區段開頭重跑 setup 再逐格推（spec §5.7 可重現規則）；逾時整個沙盒重建 | e2e：內建測試插件畫得出來、跳格結果與逐格播放相同 |
| ② | 疊放順序（§5.10）：V1 → 3D 場景（scene3d，拿 V1 當格畫面當貼圖、畫滿版）→ V2 以上疊加軌 → 2D／3D 插件（anim2d、anim3d） | Vitest（每格的圖層順序）＋e2e |
| ③ | 板子姿勢：`plane3dMath.ts`＋「漂浮的板子」3D 範本（5 個運鏡範本，頭尾自動回滿版平面，背景：內建場景／模糊原畫面／純色） | Vitest（數學）＋e2e（頭尾＝原畫面、中間板子變形） |
| ④ | 桌上螢幕範本（程式畫木紋桌與螢幕框、螢幕播影片）＋鏡頭關鍵幀（位置、看向、視角；錨定區段頭尾；頭尾接回滿版） | e2e |
| ⑤ | 吉祥物範本（基本幾何組成：走路、揮手、指向定位點） | e2e |
| ⑥ | 用說的：閘道 `/v1/ai/plane3d`（Spark）＋ Inspector 的「用說的」輸入，AI 預覽後按套用才寫進專案 | 閘道單元測試＋實測 8 句（原專案的題目）＋e2e（攔截） |
| ⑦ | Vibe特效 3D：提示詞加 three.js 插件格式與 3D API 文件（`NoColorSpace` 寫明）；沙盒 vet（setup＋幾格 update、限時） | 實測＋e2e（攔截） |
| ⑧ | WebView2 自我檢查加 3D：每格耗時、Arc 內顯上 60 秒區段 | 桌面自我檢查 |

順序：①②（底層）→ ③（板子，最確定）→ ⑥（用說的，接在板子上）→ ④⑤（場景範本）→ ⑦ → ⑧。
3D 插件跑的是原生 JS（three.js 進不了直譯器），安全只靠沙盒：沒有 same-origin 的 iframe、CSP `connect-src 'none'`、Worker 裡沒有 DOM 與 WebRTC、逾時強制終止。
