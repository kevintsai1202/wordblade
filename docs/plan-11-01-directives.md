# 導演指示（2026-11-01）

使用者在 AI Director 分頁寫指示，一行一條。指示不是另外加上去的動作：導演每個階段都看得到它們，並圍繞指示安排整份剪輯。

## 各階段

| 階段 | 怎麼用指示 |
| --- | --- |
| Spark 逐段看影片 | 逐字稿前面附上指示，請 Spark 把指示提到的東西寫進摘要和重點，並附上外框 |
| 規劃者 | 步驟 0：先讀指示，圍繞它安排構想、章節和其他項目；照指示做的項目標 `"directive":"d1"`；`treatment.directives` 要逐條交代用了哪些項目（`items`），或寫出不採用的原因（`notAdopted`） |
| 閘道規則（DirectorRules） | 照指示做的項目不受風格、次數上限、特效密度、problem、quote 這幾項限制；時間長度、不重疊、必填欄位照樣檢查。有指示漏了交代就退回重寫。指示做出來的項目全被規則擋下、又沒寫原因時，用規則的錯誤訊息當原因 |
| 審查員 | 檢查每條指示有沒有做到、不採用的原因合不合理；照指示做的項目不能被刪，閘道會把刪改成修改交回規劃者；也不能被標成可有可無（prune） |
| 前端 | 文字框輸入指示；Your directions 區逐條列出 ✓／✗ 和原因；照指示做的項目上標「Your direction」 |

## 衝突時

照規則來，但一定要寫出不採用的原因（開發者 2026-11-01 決定）。程式本身決定的剪輯（片頭、片尾、重講）不會因為指示而改變。

照指示做的項目整段落在剪掉的範圍內時（不論是規劃者的剪，還是片頭、片尾、重講這些程式決定的剪），規則會把它擋下，擋下的原因就當作不採用的理由，因為觀眾永遠看不到它。

## 玩偶

玩偶至少要 3 秒，這條由閘道規則檢查。

`action` 新增 `walk`：整段都在走，一路走到目標框，可用 `from` 指定從左邊或右邊進場，範本是 `mascot-walk`。

## 實測（logs/directives-live-1.log）

素材是 OBS 中文錄影，用 plain 風格、沿用上次的逐字稿。

- 「在 1:08 到 1:14 讓玩偶從左邊走到畫面上 Spring MVC 的標題」：做到了，產生 68–74 秒的玩偶。
- 「在 0:40 放大畫面上的程式碼」：沒採用。原因是 0:40 落在 19.0–66.4 秒的重講剪輯裡，而且那段畫面是標題頁，不是程式碼。
